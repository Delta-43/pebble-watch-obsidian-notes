| Small Icon | 80×80px | [`design/app_icon_small_80.png`](../design/app_icon_small_80.png) — generated this phase, downscaled from the 1024px master (the repo had 25/144/1024px versions, nothing at 80px) |
| Large Icon | 144×144px | [`design/app_icon_preview_144.png`](../design/app_icon_preview_144.png) — already existed, doubles as this repo's own README logo |

Separate from both: the **in-app menu icon** (shown on the watch's own app list, not the phone's Locker)
is [`watchapp/resources/images/app_icon.png`](../watchapp/resources/images/app_icon.png), exactly 25×25px
— confirmed in Phase 7 as the SDK-enforced max for that specific resource, unrelated to the two store
icons above.

**If a sideloaded install shows a blank/default icon in the phone app's Locker, that's expected, not a
bug** — confirmed by reading `coredevices/mobileapp`'s own source. A sideloaded app's `LockerEntry` (see
`PbwApp.toLockerEntry()` in `libpebble3/.../disk/pbw/PbwApp.kt`) only populates `pbwIconResourceId` (the
on-watch icon above) and leaves `iconImageUrl` — what the Locker *list* actually renders from — at its
`null` default, since that field only ever comes from `appstoreData`, which is unconditionally `null` for
every sideloaded entry. **Confirmed for real, not just predicted**: after publishing, removing the
sideloaded install and installing the app store version instead shows the icon rendering correctly — see
`docs/TROUBLESHOOTING.md`'s "Switching from a sideloaded install to the app store version" for that test
(it also confirmed the config page's webhook URL/token survive the switch automatically).

## Store description

The portal has a **single** Description field (not separate short/full) — this leads with the hard
requirement in its first sentence rather than burying it, since a store browser who installs expecting a
working note-taking app out of the box is the predictable source of "doesn't work" reviews for an
audience that could never have used this app in the first place:

```
Dictate a note on your wrist and have it saved straight into your own self-hosted Obsidian vault. Requires your own n8n instance — not a standalone note-taking app.

Delta Notes turns your Pebble into a voice inbox for Obsidian. Press SELECT (or tap the mic icon on a touchscreen model), say your note, and it lands as a plain Markdown file in your vault's Watch Inbox/ folder within seconds — no phone typing, no manual copy-paste.

This requires infrastructure you run yourself: a self-hosted n8n instance and an Obsidian vault reachable from wherever you run the companion mcp-obsidian tool (Docker Compose included). If you don't already run n8n, budget 15–20 minutes for the one-time setup — full guide in the GitHub repo's docs/SETUP.md. If you're not planning to self-host a backend, this app won't do anything useful for you.

What it does do, once set up: dictation via your watch's built-in cloud speech recognizer, a direct authenticated webhook to your n8n (no third-party service in between), and a note that syncs to your other devices the same way any other vault change does. Open source, AGPLv3 licensed.

github.com/Delta-43/pebble-watch-obsidian-notes
```

Release notes (separate, optional field on the PBW upload step): left blank for `1.0.0` — nothing to
compare against on a first submission.
